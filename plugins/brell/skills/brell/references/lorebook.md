# 로어북

로어북은 메인 프롬프트 밖에 두고, 키워드가 걸릴 때만 불러오는 항목 묶음이다. 캐릭터도 로어북 항목의 한 종류다. 키워드 개수는 SKILL.md 「사이트 규격」 표를 따른다. 캐릭터 시트는 800~1,000자로 만든다.

## 1. 항목 종류

| 종류 | 담는 것 | 발동 키 |
|---|---|---|
| 메인모드 | {{user}}의 정체·과거, 인물들의 인식, 시작 호감도, 고정 등장인물, 시작 장면, 모드 전용 규칙 | INFO 모드 문자열 + `!!모드명` |
| 서브모드 | 메인모드에 덧붙는 모드 | INFO에 덧붙는 `+이모지` 문자열 + 명령어 |
| 캐릭터 | 그 캐릭터가 장면에 있을 때만 필요한 연기 정보 (3-3 시트) | 이름+조사, 대사 키 |
| 세계관 | 연도와 사실 | 질문에 나올 구절 |
| 장소·소속·세력 | 위치 / 풍경 / 특징 | 이름+조사, 구절 |
| 발동이벤트 | 게이트, 단계형 이벤트, 기능 출력(SNS·갤·방송 등) | INFO 상태 문자열, 명령어 |
| SVG | (양식 미정) | (미정) |

## 2. 메인과 로어북의 분담

**메인은 "누구인지", 캐릭터 항목은 "어떻게 구는지", 모드 항목은 "{{user}}와 어떤 사이인지"를 맡는다.**

- 메인: 장면에 없어도 필요한 식별 정보. 캐릭터 DB 한 줄(`이름|고유코드|성별|나이|외형|성격`)과 관계도.
- 캐릭터 항목: 그 캐릭터가 장면에 있을 때만 필요한 연기 정보. {{user}}와의 관계는 쓰지 않는다. 그래야 한 캐릭터 항목을 모든 모드가 같이 쓴다.
- 모드 항목: {{user}}와 특정 인물의 관계, 시작 호감도.

| 정보 | 메인 | 캐릭터 항목 | 모드 항목 |
|---|---|---|---|
| 이름·고유코드 | DB 1·2열 | 첫 줄 `이름(코드)` | — |
| 성별·나이 | DB | 쓰지 않음 | — |
| 외형 | DB (머리색·머리모양, 눈색, 상의까지) | 쓰지 않음 | — |
| 성격 | 성격태그 3개 | 시트 전체 | — |
| 관계 | 관계도 (한쪽만 나와도 지켜야 하는 것: 혈연, 상하, 세력 간, 앙숙) | 같이 등장할 때만 의미 있는 사적 관계 (룸메이트, 팀 안의 호칭) | {{user}}와의 관계 |
| 호감도 | — | 숫자 쓰지 않음 | 시작값 |

로어북 전체는 **INFO를 스위치로 쓰는 상태 기계**다. AI가 매 턴 INFO에 고정 문자열을 찍고, 그 문자열이 다음 턴에 해당 항목을 다시 부른다. 상시 활성화 없이 규칙이 유지된다.

## 3. 항목별 양식

### 3-1. 메인모드

- 첫 줄 `🎭 모드이름 | 이모지` + "INFO 모드란에 매 턴 그대로 유지".
- 이어서 `## 과거 배경 / ## 현재 배경 / ## 관계 / ## 시작` 틀로 쓴다: {{user}} 정체 → 인물들의 인식 → 신분 → 초기 ❤️ → 고정 등장인물 → 시작 장면 → 모드 전용 규칙.
- "~설정 미적용"처럼 적용하지 않는 것을 명시한다. 화살표 사슬보다 문단으로 푼다.

### 3-2. 서브모드

- 기존 모드 이모지 뒤에 `+이모지`를 붙이게 하고 예시 한 줄을 준다.
- 끝나는 조건을 쓴다.

### 3-3. 캐릭터

캐릭터는 성격태그 3개의 조합에서 출발한다. 결과물은 캐릭터마다 둘이다: 로어북 캐릭터 시트(아래 7칸, **800~1,000자**), 메인 DB 한 줄. 분량을 줄이거나 늘리는 것은 제작자가 지시할 때만 한다. 기존 작품·기존 캐릭터를 예시로 끌어오지 않는다.

**시작 전에 한 번에 묻는다** (이미 나온 것은 다시 묻지 않는다. 답을 받기 전에는 쓰지 않는다)

> 세계관은 무엇인가요? 캐릭터는 몇 명이고, 특수성격 비율은 몇으로 할까요?

- 특수성격 비율 기본 7:3. 10명이면 특수 3명, 16명이면 5명(반올림).
- DB 열은 메인 틀의 `이름|고유코드|성별|나이|외형|성격`. 작품에 따라 열을 더할 수 있다.

**성격태그 3개를 먼저 제안하고 승인받는다**

```
1. [다정한] [겉으로 착함 속으로 음탕함] [바보]
2. [여우스러운 성격] [허나 사실 둔감] [속은 여리다]
3. [츤데레] [열혈] [허당]
```

- 세 태그는 다른 층을 맡는다: 겉모습 1 + 속 1 + 결 1. 같은 뜻 셋(냉담·무뚝뚝·과묵)은 금지.
- 짧은 한국어 구절, 15자 안쪽.
- 특수 태그는 비율만큼만, 한 종류를 두 명 이상에게 주지 않는다.
- 제작자 지정이 우선한다. 비율이 깨지면 보고에 "비율 깨짐: 특수 N명".
- 세계관상 칸을 더 달라고 하면(스킬, 이능, 직업 규칙 등) 시트 끝에 붙인다. 추가 칸도 1,000자 안에 넣는다.

**시트 양식 (7칸, 800~1,000자)**

```
이름(고유코드)
주 성격태그: [태그1] [태그2] [태그3]
성격&특징: …
핵심욕망: …
결핍: …
말투특징: …
말투예시: 조각 / 조각 / 조각 / 조각
```

| 칸 | 쓰는 법 |
|---|---|
| 이름(고유코드) | DB의 코드 규칙을 따른다. 규칙이 없으면 묻는다 |
| 주 성격태그 | 승인된 3개 그대로 |
| 성격&특징 | 태그 3개를 세계관에 맞게 "~하면 ~한다" 행동 문장으로 푼다. 겉 성격과 현재 처지에서 나오는 행동 습관을 같이 쓴다. 설명이 필요한 태그는 첫 문장에서 뜻을 푼다 |
| 핵심욕망 | 한 가지만. 성격만 보고는 짐작 안 되는 것. 성격의 반대나 옆 방향에서 고른다 |
| 결핍 | 욕망이 왜 생겼는지. 정해진 문장 틀 없이 캐릭터마다 다르게. 욕망 칸의 말을 반복하지 않는다 |
| 말투특징 | 리듬·태도를 `·`로 이은 구절 → 호칭·자칭 → 쓰지 않는 말 → 말투가 바뀌는 조건 한 문장 |
| 말투예시 | 4개, 상황 라벨 없이 조각만 `/`로 잇는다. 한 조각 15자 안쪽. 네 조각은 서로 다른 상황의 말 |

- 욕망은 입체 쪽으로 고른다. 평면: 차가운 성격 + 혼자 있고 싶다. 입체: 차가운 성격 + 누가 먼저 다가와 주길 바란다.
- 쓰지 않는 것: 말투예시의 고유명사·숫자·인상적인 비유 / 전용 물건·소품·단골 장소 / 15자를 넘는 완성 대사 / MBTI·에니어그램 코드 / 외모(DB에만) / {{user}}와의 고정 관계·호칭(모드 항목에) / 호감도 숫자 / 한자·기호 압축·코드만으로 가리키는 표현.

**차별화 규칙** (쓰기 전에 배치표 `이름 / 태그 3 / 온도 조합 / 핵심욕망`을 만들고 다 쓴 뒤 다시 확인)

1. 핵심욕망은 1인 1개, 전원 다르게.
2. 기본 온도 조합(활발/차분 × 다정/냉담 × 먼저 다가감/기다림)은 2명까지.
3. 특수 태그는 한 종류 1명.
4. 문장 틀("~해야 마음이 놓임", "속으론 ~를 바람")을 두 명 이상에게 돌려 쓰지 않는다.
5. 같은 상황 테스트: 약속에 늦은 상대 / 다른 이성 얘기 / 첫 만남 헤어질 때. 반응이 둘 이상 같으면 태그나 욕망을 바꾼다.
6. 같은 소속 안에서는 결핍·말투가 특히 겹치지 않게 한다.

**작성 순서**: 질문 → 태그 제안·승인 → 배치표 → 시트(6명이 넘으면 5명 먼저 보여 주고 승인) → DB 한 줄 압축(성격 열에 태그 3개 그대로, 외형은 자료가 있을 때만, 없으면 `(입력)`) → 보고.

**변형**
- 이중 인격: 한 항목에 두 인격의 칸을 나란히 쓰고, 둘째 인격 맨 위에 `발현:` 줄. 끝에 `[시스템] A와 B는 한 사람이며 기억을 공유하고 동시에 존재할 수 없다.` DB에는 코드가 다르므로 두 줄.
- 숨은 서사: 7칸 뒤에 `숨은 서사:` 한 줄. 같은 내용을 다른 항목에 또 쓰지 않는다.
- 모드 전용 인물: 메인 DB에 넣지 않고 이름 다음 줄에 `DB: 값|값|…` 한 줄.

**원문이 있는 인물을 옮길 때**: 원문의 사실은 하나도 빼지 않고 맞는 칸에 옮긴다. 새로 지은 내용은 "제가 정한 것"에 인물별 한 줄로 적는다. 원문의 "비밀" 설정은 넣으라고 하기 전에는 넣지 않는다.

**보고**: 첫 줄에 몇 명·특수 N명(비율 유지/깨짐) → 시트 전문(한 명씩 코드블록) → DB 한 줄.

### 3-4. 세계관

- 연도와 사실만 한 줄씩. 문장 하나에 사실 하나.
- 끝에 `※ 누군가 이 내용을 물으면 인물은 자기 나이·출신·직책으로 알 만한 범위에서 자기 말투로 답한다`.

### 3-5. 장소·소속·세력

- `위치 / 풍경 / 특징` 세 줄. 풍경은 짧은 명사 나열.
- 분위기 묘사 문장은 쓰지 않는다(켜질 때마다 같은 묘사가 되풀이된다).

### 3-6. 발동이벤트

- **게이트**: 입장 시 상태 변경 → 내부 수준 → 1관문 → 2관문 보상 → 수치 보상 → 변수 이벤트 목록("상황에 맞는 1~2개만, 전부 동시 금지") → 종료 시 상태 복귀.
- **단계형 이벤트**: 명령어 키만 두면 N턴 뒤 꺼진다. 진행 단계를 INFO 문자열로 찍게 하고 그것을 키로 쓴다.
- **기능 출력**(SNS·갤·방송 등): 발동 조건 → 출력 단계 번호 → 형식. 본문의 명령어와 키가 같아야 한다. 양식에 "고정 아이콘 외 이모지 금지"를 넣는다.
- "우연히 마주친다" 같은 확률·빈도 규칙, 등장 유도는 넣지 않는다.

### 3-7. SVG

양식 미정. 제작자에게 확인한 뒤 채운다.

## 4. 발동 키

| 방식 | 대상 | 키 |
|---|---|---|
| 상태 고정형 | 메인모드, 서브모드, 게이트 | INFO에 찍히는 문자열 그대로 (`🎭 일반모드`, `\| 1️⃣`, `게이트색상:(🟡)`) |
| 명령어형 | 모드 진입, 기능 출력 | `!!모드명`, `!랭킹전` |
| 이름+조사형 | 캐릭터, 소속, 세력 | `이름이/가, 은/는, 에게, 을/를, 의, 과/와, 한테` + 대사 키 |
| 화제 구절형 | 세계관, 장소 | 두 단어 이상 구절 (`관리국 설립`). 질문에 나올 말로 잡는다 |

**캐릭터 키**
- 대사 키는 사이트 대사양식을 따른다: `**이름`(챗플·바베·루나·엘린·우마이), `@이름@`(젠잇), `<<이름>>`(에덴).
- 이름만 단독으로 넣지 않는다. INFO의 `이름|❤️` 줄 때문에 매 턴 켜진다.
- 받침에 맞는 조사만 넣는다(받침 있음: 이·은·을·과 / 없음: 가·는·를·와).
- 키워드가 5개뿐인 사이트는 대사 키 → 주격 → 보조사 → `에게` → 목적격 순으로 남긴다.

**이모지**
- 이모지 단독 키는 쓰지 않는다(댓글·게시판 양식에서 오발동). 예외는 검증된 `💕` 하나. `🔞`는 INFO에 매 턴 찍히므로 키로 쓰면 상시 항목이 된다.
- 변형 선택자(U+FE0F)가 붙는 이모지(1️⃣ ♦️ ♀️ ⚔️)는 FE0F가 있는 표기와 없는 표기, 공백 있는/없는 표기를 다 넣는다. 코드포인트를 찍어 확인한다.

**넓은 키·겹침**
- 한 단어짜리 넓은 키(`갤러리`, `커뮤니티`)와 INFO에 매 턴 찍히는 단어는 피한다. 소속 항목은 `백호대는`, `백호대가`처럼 조사를 붙인다.
- 부분일치 함정: `!X`는 `!!X`에도 걸리고, `연계모드`는 `연계모드2`에도 걸린다. 끄는 키워드로 막거나 항목을 합친다.
- 완전일치 사이트(챗플)에서는 반대로 표기별 키를 따로 넣는다.
- 모드가 바뀔 때 이전 모드 키가 남아 겹치지 않게 끄는 키워드를 단다. 끄는 키워드가 없는 사이트는 본문 규칙으로 막는다("4️⃣ 표기 시 3️⃣ 규칙 무효").

**활성화 설정**
- 인트로 활성화·상시 활성화는 전부 끈다.
- 인트로 문구가 모드 키를 건드리지 않게 `!!**일반**모드`처럼 끊어 쓴다. 설명 줄에 캐릭터 이름을 쓰지 않는다.

## 5. 목록 순서

메인모드 → 서브모드 → 발동이벤트(기능 출력) → 캐릭터 → 발동이벤트(게이트) → 세계관 → 장소·소속·세력 → SVG → NSFW. 동시 적용 개수 제한이 있는 곳(바베)은 중요한 항목을 위로.

## 6. 기존 로어북을 고칠 때

1. 읽기: 새 탭에서 메인과 로어북 전문을 읽고 항목별 글자 수·양식·키를 표로 만든다.
2. 진단 보고: 이 파일 기준과 다른 점(양식 혼재, 코드 표기, 분량, 개별 오류, 메인과 불일치)을 보고하고 범위를 묻는다.
3. 시범 5개 → 승인 → 전체.
4. 넣기: 제작자가 보는 탭에. 순서 바꾸기는 적용됐는지 다시 읽어 확인한다.
5. 검증: 7절 검수표.

구조(항목 분리·키 정리)만 손보고 본문을 옛 양식으로 두면 끝난 것이 아니다. 본문을 못 바꿨으면 못 바꿨다고 보고한다.

## 7. 검수표

**메인 ↔ 로어북**
- 메인 DB 줄 수와 캐릭터 항목 수를 대조하고, 한쪽에만 있는 인물을 적는다.
- 직책·호칭 표기가 같은가.
- 메인 성격 열의 태그와 시트의 주 성격태그가 같은가.
- 숨은 설정이 두 군데 이상에 중복돼 있지 않은가. 다른 작품의 문장이 섞이지 않았는가.

**항목 본문**
- 양식, 글자 수, 쓰지 않는 것. 따옴표가 닫혔는가, 칸 이름이 다른 줄에 붙지 않았는가.

**발동 테스트** (우마이 로어북 테스트, 또는 같은 원리로 직접 대조)
- INFO 한 줄(`이름|❤️:0|…`)만 넣었을 때 캐릭터 항목이 안 켜지는가.
- 대사 한 줄을 넣었을 때 그 캐릭터만 켜지는가.
- 인트로 원문을 넣었을 때 의도한 모드 하나와 그 장면 인물만 켜지는가.
- 상태 문자열이 자기 항목만 부르는가.
- 평범한 대화 문장에 세계관·기능 항목이 켜지지 않는가.
