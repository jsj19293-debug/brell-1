# /패치 — 업데이트 패치

이미 나온 작품에 무엇이든 추가·수정할 때 쓴다: 캐릭터 추가·수정, 장소, 에셋 번호, 모드·서브모드, 기능 출력(SVG·갤러리), 수치 규칙. 한 군데만 고치고 끝내지 않는다. **그 변경이 닿는 곳을 전부 찾아 같이 고치고, 고친 곳마다 확인한 뒤 보고한다.**

## 0. 요청 정리 (먼저 묻지 말고 읽는다)

1. 대상 작품·사이트를 확인한다. 열린 편집화면이 있으면 그것부터 쓴다(사이트 파일 「편집화면 진입」).
2. 메인 프롬프트·로어북 전문을 읽는다(사이트 파일 「읽기」). 이미지가 첨부됐으면 외형·노출 정도를 직접 본다.
3. 변경 종류를 정한다: 추가 / 수정 / 삭제 / 번호·범위 변경.

## 1. 영향 범위 찾기

아래 표를 위에서부터 훑으며 "이 변경이 닿는가"를 적는다. 검색어는 고유코드 범위(`M01~M18`), 인원수(`18명`), 이름, 에셋 번호, 장소명이다.

| 층 | 볼 곳 | 자주 걸리는 것 |
|---|---|---|
| 메인 프롬프트 | DB 줄, 관계도, 장소, 상황코드표, 이미지 출력 규칙, 매칭목록·SVG 포맷 설명, INFO 템플릿 | `M01~Mxx` 범위, "N명 중 6명", 코드 범위 표기 |
| 로어북 | 캐릭터 시트, 모드(시작 인물·장소), 시스템 항목(디버그 기준 포맷), 커스텀모드, 갤러리·기능 출력 | 디버그·커스텀모드 안의 코드 범위, 키 겹침 |
| 이미지 저장소 | `brell.uk/{코드}/{번호}.webp` | 새 코드 폴더·필요 번호(1~96, 91·92 프사) 존재 |
| 워커(SVG) | mannam(매칭목록), mannam2(채팅), mannam4·5(영상통화), mannam6(월영 소식통 갤러리) | 워커 안 회원 배열·코드 검사. mannam6은 `img=코드/번호` 인증 사진용 WOMEN 배열이 따로 있다(2026-10 기준 M17 제외) |
| 홈페이지 | 한 파일 HTML: `SITE_CONFIG`(profiles·regions), `pages.meeting`의 `people`, 이용 안내(`#guide .screens`) SVG 카드, `I18N`(영·일·중) | 회원 수 표기, 장소 소속, 새 기능 카드·안내 문장("아래 N장"), 번역 누락 |
| 다른 판본 | 다른 사이트 이식본, 에덴 언어판 | 같은 변경을 따라 넣을지 제작자에게 묻는다 |

## 2. 계획 보고 → 승인

- 표로 보고한다: `층 | 바꿀 곳 | 지금 → 바꿀 값`. 표 밑에 정해야 할 것(분량 한도 초과, 이름·태그, 장소 소속, 다른 판본 반영 여부)만 적는다.
- 캐릭터 추가는 `lorebook.md` 3-3대로 이름·이모지·나이·직업·혼인·등급·외형·성격태그 3개를 먼저 승인받는다. 이름은 기존 인물과 글자가 겹치지 않게, 외형이 겹치면 구분점을 적는다.
- 사이트 작업 기준 글자 수를 넘으면 넘는 양을 적고 묻는다. 제작자가 한도를 따로 정하면 그 값을 따른다.
- 승인 전에는 아무것도 넣지 않는다. 승인 범위 밖의 것은 고치지 않는다(관계도 등을 "임의로" 맡기면 그건 승인으로 본다).

## 3. 적용 순서

1. **메인 프롬프트**: 문자열을 앵커로 찾아 바꾼다. 앵커가 정확히 1번 나올 때만 바꾸고, 아니면 멈춘다. 넣은 뒤 메뉴를 옮겼다 돌아와 다시 읽어 확인한다.
2. **로어북**: 기존 항목 양식을 그대로 따른다(작품마다 시트 칸이 다를 수 있다. 그 작품의 다른 항목이 기준). 키 개수·조사·스캔 범위도 기존 항목에 맞춘다. 넣은 뒤 목록을 다시 읽어 개수·순서·내용을 확인한다.
3. **워커**: 대시보드에서 읽기만 한다. 읽기는 `/api/v4/accounts/{계정}/workers/scripts/{워커}/content/v2`(응답 헤더 `cf-entrypoint`가 실제로 도는 파일). **배포(PUT·Deploy)는 Claude가 하지 않는다.** 바꿀 위치(어느 줄 아래)와 넣을 코드를 코드블록으로 주고 제작자가 붙여 넣는다. 배포 뒤 다시 확인해 준다고 적는다.
4. **홈페이지**: `scripts/homepage_patch.py`로 넣는다(아래). 번역(영·일·중)은 기존 I18N 말투·표기를 따른다: 월영→Wolyeong/月影, 영어 아포스트로피는 `’`.
5. 다른 판본은 승인받은 경우만 같은 변경을 넣는다(`port.md`, `translate.md`).

## 4. 검증 (보고 전에 전부)

- 메인: 새 값 포함·옛 범위 표기(`M01~M18`) 0개·글자 수.
- 로어북: 우마이는 무료 「로어북 테스트」로 대사 줄 → 그 인물만 켜짐, 이름+조사 → 켜짐, INFO 줄만 → 안 켜짐. 테스트 창 textarea는 3개이며 [1]=직전 AI 응답, [2]=보낼 메시지.
- 이미지: 새 탭에서 `Image()`로 필요한 번호를 불러 본다. 직접 열어 외형·노출을 눈으로 확인한다.
- 워커: 새 코드를 넣은 SVG 주소를 직접 연다. 오류 문구("code는 M01~M18 중 하나") 또는 새 코드를 빼고 그린 목록이면 "워커 수정 필요". SVG는 화면 캡처가 안 될 수 있어 `text`·`image` 요소를 읽어 판단한다.
- 홈페이지: `scripts/homepage_check.py`로 4개 언어 확인.
- 프롬프트와 워커의 번호 규칙이 서로 다르면(예: 채팅 사진 번호) 보고에 같이 적는다.

## 5. 홈페이지 스크립트

```
python3 scripts/homepage_patch.py 원본.html spec.json 결과.html
python3 scripts/homepage_check.py 결과.html M19 M20
```

- spec 키: `profiles_add`·`profiles_update`(프사·비밀사진 3장), `people_add`·`people_update`(회원 카드: code·name·age·job·tier·glyph·bg·w·look·tags·message·work·free·late·tease·whisper·place·react·weak·locks), `buildings_add`·`building_members`(장소·소속), `text_replace`(where=meeting|phone|outer, 화면에 안 나오는 주석은 `"check": false`), `i18n_add`(`"한국어": [영어, 일본어, 중국어]`).
- 예시: `scripts/example_spec_M19_M20.json`(2026-10-17 권해솔·차미연 추가).
- 원본 서식이 예상과 다르면 스크립트가 멈춘다. 그때는 손으로 고치지 말고 달라진 구조를 보고하고 "스킬 갱신 필요"로 적는다.
- 번역 누락이 1개라도 있으면 끝난 것이 아니다. 추가 후 다시 돌린다.
- 비밀사진은 이미지 번호 91(프사)·93·94·95를 기본으로 쓰고, 사진을 보고 제목·한마디·lewd(0~4)를 정한다. 사진 한마디는 앱 말투, 회원 카드 문구는 등급 수위(TIERS)를 따른다.
- 이용 안내 카드: SVG 기능(매칭목록·채팅·영상통화 2종·월영 소식통 갤러리)마다 `<article class="screen">` 한 장 = 실제 워커 주소 이미지 + `h3` + 설명 `p` + 입력 예시 `kw` 코드. 새 SVG 기능이 생기면 카드를 추가하고 머리말의 장수("아래 다섯 장")도 고친다. 카드 이미지 주소는 실제로 열어 그려지는지 확인한다. 입력 예시는 그 기능 로어북 키에 걸리는 말로 고른다. 카드 글자는 `text_replace`(where=meeting, 앵커=직전 카드의 kw 끝)로 넣고, 문장마다 i18n을 단다. 이미지 주소 안 한글은 번역하지 않는다.
- 결과 파일은 원본 이름 그대로 출력 폴더에 두고 SendUserFile로 준다.

## 6. 보고

1. 첫 줄: 끝난 것 / 제작자가 해야 할 것(저장·발행, 워커 배포)을 한 문장으로.
2. 층별 결과: 바꾼 곳과 확인 결과. 숫자(글자 수, 항목 수, 회원 수)를 적는다.
3. 워커 붙여 넣을 코드(있으면).
4. 확인 못 한 것과 이유(접근 막힘, 화면 캡처 불가 등).
5. 이름 오타처럼 제작자 말과 다르게 처리한 것은 한 줄로 밝힌다.
